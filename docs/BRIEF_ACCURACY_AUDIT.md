## Findings requiring action across lessons

1. **High — truthful assumptions are mostly hidden.** Drivers place necessary qualifiers in `ModelResult.note` and/or `detailJson`, but `VlabApp.cs:376` (`InstrumentReadings`), `:462` (`ShowResults`) and `:468` (`ShowNotebook`) show readings and the short `model` label, not the detailed notes. Consequently the learner is not told about the actual P02 muzzle height, B02 untimed state images, cooling B04/B05 samples, or illustrative B06 solvents. Add bilingual learner-visible limitations and retain them with the recorded attempt; a hidden JSON field is insufficient.
2. **High — controlled grouping ignores actual configuration metadata.** `ExperimentNotebook.cs:122` includes only `spec.parameters` and `record.model`. It does not include C02 reversed leads, M02 pivot mark, M04 selected belt span, M06 follower type, C05 serial lineage, or M07 actual sample identity from detail. In particular C02 opposite signs can be averaged as replicates under identical parameters. Include the conditions that change the measurement; do not average unrelated setups.
3. **High — P07 requested fixed-total-mass graph cannot be made.** `ExperimentNotebook.cs:61,120,122` exposes raw parameter X choices and holds every other parameter fixed. Varying hanger mass while reducing cart mass at fixed total mass splits every point into a separate group. Add derived external-force X, explicit total-mass control, and the separate inverse-total-mass comparison at fixed hanging force. P02 also lacks the specifically requested `R` versus `v0²` X transformation.
4. **Medium — preparation success is not full lesson completion.** Most repeat counts and named control comparisons are available only by independently restarting, with no progression that requests or checks the full series. The notebook honestly refuses to invent missing points, but the guide immediately recommends recording when one trial is possible (`LessonGuide.cs:113`), then stops teaching the broader experiment. Distinguish a recorded trial from a completed brief and guide the next controlled comparison.

## Guidance and clock assessment

The guide observes instrument state and chooses an actionable next step; it does not call Prepare/Operate/Measure or classify an image (`LessonGuide.cs:15`). Source masks and stage checks do not automatically fill learner counts. These are sound foundations for low-tech users.

Live instrument modal handling is now deliberate: `VlabApp.cs` calls `Modal(...,true)` for instruments and allows `Session.Advance` only on activity routes with live modals; `SyncAuthority` freezes SDK authorities on non-live routes. `ExperimentSession.cs:91–107` shares pause/input-loss/invalid authority stops. This source review found no general observation-clock leak, but it is not a fresh runtime timing proof. The projectile retains a separate single FixedUpdate flight clock; confirm temporal alignment with Session elapsed in runtime tests.

Specific guide gaps: biological image focusing gives a numerical target rather than visible image sharpness; VI generic failure fallback hides many concrete source-capacity reasons; larger repeat/control-comparison assignments stop after one recordable trial. These require usable next-step guidance without exposing the correct biological classifications or substituting model predictions for observations.

## Conclusion

The staged product has substantial real source-kit state and observation work. It is not yet proven faithful to every named experiment brief. Highest-priority fixes are learner-visible assumptions, configuration-aware notebook grouping, actual gate-derived P07/P08 results, B02 concentration-response scope, and reverse-drive M01/M04 comparisons. Preserve original geometry while making valid articulation/configuration changes.
